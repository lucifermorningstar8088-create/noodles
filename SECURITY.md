# Security Policy

## Supported versions

Security fixes will be prioritized for the latest supported version. Until a release/support policy is published, assume only the latest default-branch state is under active development.

## Reporting a vulnerability

**Please do not disclose suspected vulnerabilities in a public issue, pull request, discussion, or social post.**

Preferred channel: use GitHub's **Report a vulnerability** option on this repository's **Security** tab, if that private reporting feature is available.

The repository's private vulnerability-reporting setting has not been verified as enabled. If the private reporting option is not visible, do not post exploit details or sensitive proof-of-concept material publicly. Ask the repository maintainer through a verified private contact channel to enable private reporting or publish a monitored security contact before sending sensitive details. No unverified email address or contact route is provided here.

When reporting privately, include:
- Affected commit or version and relevant environment.
- Security impact and realistic conditions required to reproduce it.
- Minimal reproduction steps and sanitized logs, without secrets or personal data.
- Any known mitigation, if available.

Please allow the maintainer reasonable time to acknowledge and investigate a report before public disclosure. Do not access, modify, or exfiltrate data that is not yours while investigating.
